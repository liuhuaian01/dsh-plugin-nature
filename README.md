# nature · 中文写作体检

让中文写出来像正常人说话。

粘贴一段中文稿，它告诉你哪里像机器写的：公文式过渡语、万能时代背景、结尾强行升华、抽象黑话、欧化长句、「的」字长链、句段过于整齐，以及「通篇没有一个具体数字或人」。按 11 个文体分别判定，再给出能直接照着改的处方。

规则库和扫描引擎是确定性的——不调模型、不联网，每一分都能追到某条具体规则上。

## 先说清楚它不是什么

**它不判断作者身份。**

这是最容易用错的地方，也是我自己踩过的坑：第一版写完，我拿一段纯手写的小说去跑，得到「40 分 C 级 · 明显的 AI 腔」——完全错了。那段文字只是用了网文常见的写法和有几个错别字，跟 AI 没有半点关系。

原因很简单：**真人写作和 AI 写作会共享大量模式。** 真人也会用对举句式，也会写「心中满是悲凉」，也会把「的」写成「地」。规则引擎能看见模式，看不见作者。

所以输出拆成三类，并且明确各自的含义：

| 类别 | 说明什么 | 是否计入分数 |
| --- | --- | --- |
| **模板腔信号** | 套话、万能背景、升华结尾、行业黑话、翻译腔——真人写小说几乎不会这么写 | 计入 |
| **节奏问题** | 句子被切碎，或句长过于整齐 | 计入 |
| **文字错误** | 错别字、「的／地」误用。谁写的都该改 | 不计入，单独列 |
| **编辑建议** | 情绪直陈、排版、ASCII 标点这类口味问题 | 不计入，单独列 |

指标名字也从「AI 味评分」改成了**「模板腔指数」**。它衡量文本里的模板化痕迹有多重，不衡量「这段是不是 AI 写的」。

另外，修辞类规则（对举句式、排比、破折号、网络梗）全部改成密度判定：真人写四千字用一次「不仅……而且」完全正常，只有密集出现才可疑。

## 装了什么

装进 profile 后有**三个**东西同时工作：

| 组件 | 作用 | 何时生效 |
| --- | --- | --- |
| `nature` 工具 | 对一段中文做确定性扫描，返回模板腔信号 + 用字错误 + 编辑建议 + 结构性指标 + 改写处方 | 模型或你主动调用 |
| 常驻提示片段 | 精简版「说人话」守则，每一轮都在系统提示里 | 一直 |
| `nature-chinese` 技能 | 完整方法论：必删清单、句式改造、十一种文体写法、二十二条改写对照、自检表 | 按需加载，不占常驻上下文 |

工具本身**不调用模型**，只做检查和开方；真正的改写由调用它的模型完成。所以它快、可解释、零额外成本，而且每一分的扣分都能追溯到某条规则。

处方也认这个账：**如果没有任何模板腔问题，它会直接说「这段不需要去模板腔」**，只列要改的错字，并明确写上「不要把长句拆短，不要重排段落，不要改语序」。

## 安装

```bash
dsh plugin install file:E:/path/to/dsh-plugin-nature
```

或者直接告诉模型：把这个目录装成插件，工具名应该是 `nature`。

装完**重启 DSH** 才会加载，因为 profile 只在启动时重新组合。重启后确认三件事：

1. 工具列表里出现 `nature`
2. 技能目录里出现 `nature-chinese`
3. 直接说「帮我把这段去掉 AI 味」，模型应当主动调用 `nature`

配置项见下表，全部可选；不配也能用。

## 怎么用

**改写一段稿子**

> 帮我把下面这段去一下 AI 味，是给公众号写的：
> （粘贴正文）

模型会调用 `nature`，拿到诊断和处方，然后按处方直接给出改写稿。默认不回显诊断，你要看诊断就明说「先给我看诊断」。

**只做检查不改**

> 用 nature 扫一下这段，告诉我哪儿像机器写的。

**指定文体和强度**

工具支持五个参数：

- `genre`：11 个文体，处方和节奏画像都跟着变——`general`（日常与说明）、`media`（自媒体推文）、`script`（口播稿、视频脚本）、`fiction`（小说剧本）、`webnovel`（网文连载）、`report`（报告、公文、商务）、`tech`（技术文档）、`news`（新闻媒体）、`business`（财经商业分析）、`commentary`（分析评论专栏）、`proposal`（方案策划、提案）。每个文体的「必须有」和「不要有」不同，判「碎片化」的阈值也不同。传了不认识的文体会回落 `general`。
- `strength`：`light` 只删套话保留结构；`standard` 重组句子段落；`rewrite` 只留事实结论推倒重写。
- `keep`：必须原样保留的内容，比如「数字不要改」「保留原文的判断方向」。
- `before`：改之前的原文。传了就出「改前改后」对照——哪些问题解决了、哪些还没处理、哪些是这次改稿**新引入**的，外加分数和长度变化。改完稿做验收时用。
- `locale`：`zh-CN`（默认）、`zh-TW`、`zh-HK`。默认会标出大陆文本里混入的港台用词。

**报告太长怎么办**

真实稿子命中十来个类目是常事。把每一条都读完再动手，大多数人会停在「我知道了」那一步，一个都不改。所以命中四类以上时，报告在详表前面先给一节「如果只改三处」：按扣分从多到少排，附上各自扣了多少分、前三条合起来占总扣分的几成。

前三名常常并列——density 类规则在两倍封顶，超 3 倍和超 27 倍都拿同样的分。这时候顺序按**超阈值的倍数**排，报告里会写出来（「扣 16 分，超阈值 6.5 倍」）。分数看不出差别的地方，倍数还留着真实差距。

试过把封顶从两倍放到八倍来拉开分差，方向是错的：AI 稿全降、真人稿反而涨。真人也写高密度文本——新闻通稿的「负责人表示」、财经稿的行业词——放大高密度区间等于放大真人的真实特征。并列的问题只能靠排序解决，不能靠抬分。

**处方到底管不管用**

拿 `ai-report-baseline`（模型默认写的季度运营报告，99 分 E 级）自己走了一遍闭环：不看规则，只按报告的处方改——结论挪到第一段、每个判断配数字、风险写在建议前面、补负责人和时间。改完 435 字，**99 → 7 分 A 级**。

这次闭环顺带抓到一条误报：「从 6 个渠道收到 3 个，单渠道日均新增从 800 提到 1400」被「从……到……」那条规则当成排比扣了 14 分。问题是「收到」的「到」是动词的一部分，不是方向词。用反向断言把「收／达／得／找／遇」这一批排除掉，真排比（「从产品设计到用户运营，从技术架构到市场推广」）照样报。

**八个文体都走一遍，四处新误报**

把剩下七个文体也闭环了：每份 AI 基线稿不看规则、只按处方改写，要求回到 0 分。结果 news 47→0、script 72→0、media 55→0、fiction 69→0、commentary 37→0、tech 50→0、proposal 35→0。**处方对每个文体都指对了地方。**

但改后的稿子第一遍也被打回去四次，查下去全是误报：

1. **「落地窗」被当黑话「落地」**。词表匹配是子串匹配，黑话「落地」撞上了家具和旅行的常用词。加了个 `excludeAfter` 字段——「落地」后面紧跟「窗／灯／扇／镜／柜／床／面／价／签／式」时不算。比把词从词表删掉精确，比给每个词单写一条正则省事。
2. **破折号被当「的」字长链**。「第二次不买——现在的复购率就是这么来的」被连成一条链读。破折号是断句，前后各一句，把它拆开就不成立了，所以排除集里加了破折号。
3. **「也就是说」被当公文过渡语**。这条原来是「出现即报」。实测 25 份语料才发现它**是负区分度**：真人用得多（虎嗅稿 4 处、李书福演讲 1 处、产业评论 1 处），8 份 AI 基线稿加起来只有 1 处。改成密度判据，千字两次以上才报——它的价值是「这词该删」，不是「用了就是 AI」。
4. **修这一类时挖出一个隐藏更久的 bug**：`compilePhraseGroup` 只挑固定几个字段复制到新对象，`genreThresholds` 和 `exceptGenres` 从来没被带过去。也就是说 jargon 的「技术文档门槛 2.0」从加进去那天起就没生效过。字段漏传这种 bug 不会报错、不会让测试变红，只会让某个规则一直按默认值跑。

这件事值得记：**规则写得再准，也会在真实文本里撞到它没有预料到的用法。** 处方改完的稿子，同时也是新语料——而且是最好用的那批，因为它要求是 0 分，任何非零都是误报，判据是硬的。

**试过自动判体裁，没做成，撤了**

「用户不知道该传哪个 genre」是个真问题：同一份李书福演讲，按 script 扫是 5 分，按 report 扫是 28 分。差二十几分，选错就得到完全相反的结论。

先后试了两条路，都失败：

1. **特征指纹**。给每个体裁写一组判别特征（记者署名、章节号、代码块、财务词……），打分取最高。32 份语料上判对 8、判错 11、弃权 13。原因是我靠常识写特征，而中文里「目标」「策略」「引号」到处都是——新华网通稿里嘉宾发言的引号，把「对话引号」这条 fiction 特征顶过了线，通稿被判成网文。
2. **比分数，选最低的文体**。听着合理，实测更糟：2519 字的新华网通稿在 8 个文体下都是 25 分，三个是 31 分。分数高低根本不携带体裁信息——节奏阈值是按体裁给的，script 和 tech 本来就宽，任何文本在它们下面都容易 0 分。

结论：**猜错比不猜更害人**。这插件是拿来改稿的，报一个自己都没把握的体裁，调用方会照错误的读者预期动手，把一份合格的口播稿按报告的标准拆一遍。所以只保留「换个文体少扣 N 分」的提示，让人自己定，不替人猜。

**改稿从哪一段下手**

命中散在全文时，按规则清单跳着改要来回翻稿子。报告里加了一节「先改哪几段」：按段统计命中的规则类目数，排前三，一段一段处理。同一段里的几处往往能一起收拾掉。

统计只用会扣分的那两类。用字错误和排版建议虽然多，但分散在各处，混进来会把「哪段问题最大」算成一锅粥。段号由行号映射（段落按非空行算，一个非空行就是一段），前缀和一次算完，不用重扫。

| `promptTone` | `balanced` | `strict` 会额外禁掉对举句式、结尾升华，并要求句段长短交错。 |

| `genre` | `general` | `nature` 工具的默认文体。 |
| `strictness` | `standard` | `nature` 工具的默认改写强度。 |
| `customBannedWords` | `[]` | 追加到必删清单的词，会进规则库也算进技能。 |
| `extraRules` | `""` | 追加到常驻守则和技能末尾的一句话要求。 |

## 规则库覆盖什么

`lib/rules.js` 里是全部规则，分四组：

**套话层**：公文过渡语（值得注意的是／综上所述／由此可见）、万能开场背景（在当今社会／随着科技的发展）、结尾升华（让我们共同／未来可期／这正是……的意义所在）、虚高程度副词、行业黑话、去动词化（进行讨论／加以优化）、名词化（可操作性／必要性）、翻译腔固定搭配、概括性形容词、滥用「我们」、骑墙表态。

**句式层**：不是……而是……、不仅……更是……、既……又……、无论……还是……都……、与其说……不如说……、正是……才……、从……到……从……到……、首先其次最后、破折号滥用、冒号引出并列短语。

**中文语感层**：「的」字长链（一句话连挂三个「的」）、关联词冗余、欧化被动（被……所……）、省略号与引号的中文写法、港台用词混入。

**节奏层（统计判定，不是正则）**：这一层专门治「断句离谱」，而且做的是**双向**判断——

- *切碎了*：句号过密（逗号／句号比过低）、短句连续成串、平均句长掉到文体下限以下、一句一段。
- *太整齐*：句长全都差不多、主语连续重复（中文本可承前省略，反复补「他」往往是句子被切碎的副作用）。

两个方向都必须报，因为**只会喊「拆短句」的检查器本身就会把中文写坏**。中文的句子边界靠语气和语义，不靠语法结构；逗号串起一串小句、最后才落句号，是正常且成熟的写法。真正该拆的只有定语堆叠的欧化长句。

**反向陷阱**：堆语气词的「伪口语」（说白了／反正／对吧密度过高）、网络烂梗堆砌、感叹号连用。去 AI 味最容易掉进的坑是把书面腔换成网红腔，这几条专门拦这个。

除了规则命中，还看九个结构性指标：平均句长、逗号／句号比、最长连续短句、句长变异系数、段长变异系数、一句一段占比、每千字「的」、每千字具体锚点（数字／日期／引语／专名）、每千字口语标记。节奏相关的几项按文体取值——口播稿天生短、报告天生克制，用一把尺子量会把正常文本判成碎片化。

**模板腔指数**是可解释的：每一分都来自某条规则或某个指标，报告里会逐条列出来。0–19 分是 A（几乎没有模板痕迹），20–39 是 B，40–59 是 C，60–79 是 D，80 以上是 E。用字错误和编辑建议不进这个分数。

三处容易踩的细节：

**词表长词优先。** 词表里「极大地」和「极大地提升」同时存在，正则如果不排序，短词会先吃掉长词的前半截——报告只能说「你用了极大地」，说不出完整的搭配。所以 `anyOf` 在拼正则前按长度倒序。

**纯数字串不算长句。** 一串哈希、坐标或时间戳去掉标点后也能超过 70 字，但它不是长句：读者一眼扫过去就跳过了，不会累。长句统计要求中文占比不低于三成半。

**分数封顶但累计分保留。** 指数上限 100，但内部扣分累计会一起返回。87 分和 130 分都是 E 级、改法都是重写，可「爆表多少」决定还能不能挑着改——到了 130 就别挑了。报告在封顶时会标出累计分。

**密度在短文本上要打折。** 密度是「每千字几处」，分母是字数。21 字的稿子里冒一句「值得注意的是」，密度会算成 47.6/千字，是阈值的二十四倍，和 500 字里刷五次拿一样的分。但一次就是一次。所以三百字以下的文本按命中次数再乘一个系数（一次一半、两次以上全额）。三百字以上不打折——一稿的 AI 味常常是十几类各出现一次，按次数打折会把这类正确的命中一起压下去。

**两类规则的量级要拉平。** 有些毛病是密度型的（黑话、空转副词，越密越重），有些是出现即问题的（「在当今数字化浪潮下」、升华结尾、翻译腔、「的」字长链）。后者原来单次只扣 3 到 5 分，同一个位置换成一条密度规则能扣 16 分，差五倍没道理——它们都是「看到就该删」。现在单次按 3 倍严重度起算，上限仍封在 4 倍，长文里不会一票否决。

**短文本要说明「没查到什么」。** 节奏类规则要六句以上才跑，段落结构类要三段以上。同一份稿子截前两百字扫，分数往往只有全文的三分之一——不是短的那一段更干净，是能查的项更少。所以文本不够长时，报告里会单列一节讲清楚哪些检查没跑，并提醒别拿这个分数和整篇稿子的分数比。报个低分让它放心，比报错更糟。

**同样四十分，改法可能完全不同。** 全是行业黑话，把词换掉就行，句子骨架能留；全是万能开场和升华结尾，那些话本身不假，是位置不对，挪走就好；全是节奏问题，词和位置都对，得重排长短和顺序。三条路花的时间差好几倍，所以报告第一屏会先给一句「问题主要在什么上」。不区分这一层，用户看到一堆命中项只会觉得哪儿都不对，然后一处都不改。

**占比不够，还要给绝对分。** 同样「占 86%」，一层扣 8 分是顺手改改，扣 80 分得推倒重来。所以病灶那一行会写「扣 56 分，占 86%」，再补一句「这一层处理完，大概能从 65 降到 9，剩下的主要是位置」——让用户先知道改这一层值不值、改完还剩什么。只有一层有扣分时说「基本就干净了」。

**改了一半的稿子是最常见的那种。** 三组语料各有各的盲区：真人稿只证明「不该报的没报」，AI 基线稿只证明「该报的报了」。真实的活儿是改一半——前半段还是八股，后半段已经落到了具体数字上。这种稿子必须两件事同时成立：前半段的毛病照报，后半段的真数字一个字都不许碰。`test/smoke.mjs` 第 25 节拿一份六段稿子验这件事，顺带撞出一个句型问题——「从 11 步砍到 4 步，从 6 天压到 1 天半」和「从产品设计到用户运营，从技术架构到市场推广」是同一个句型，前者是真对比、后者是摆架子。规则加了 `requireNoDigit`：填了数字的放过。句型本身是中性的，要看里面填的是不是真东西。

**长文里局部集中的套话会被平均掉。** 密度算的是全文每千字多少处，这个口径对整篇公平，对局部不公平：三千字里夹着三百字全是黑话，按全文算不到一处。试过按块切、取最狠的那一段去扣分，结果真人公文和真技术文档全被误伤——政府工作报告从 5 分涨到 37 分，掘金技术文从 1 分涨到 26 分。原因是文体校准本来就是按全文统计的，分块等于把这个校准拆了。

所以拆成两件事：**评分不动，另外定位。** 超过五千字时，按段统计原始命中（不管有没有过全文阈值），把明显高于平均的段落指出来：

```
## 局部特别密的地方

全文的分数按整篇算，所以某一段特别密会被平均掉。这几段单独看比整篇密得多：

- 第 26 段：14 处（全文平均每段 0.3 处）

分数没算这一段，要改就单独把它拎出来扫一遍。
```

整篇分数本来就低时（低于二十分），文案换成「这几段很可能只是这个文体的惯例，看一眼就行」——公文的政策列举、财经稿的行业词都是这种，不能让人以为整篇到处是雷。

定位和评分能分开，是因为它们对校准的依赖不一样：分数要跨文体比较，所以必须按全文统一口径；定位只是「这一段比别的地方密」，是段内相对比较，不需要跨文体校准。

顺带修了两处文案错配。「没查到的部分」那节结尾原来说「短文本的分数天然偏低」——长文说这句是误导，而且短文本里套话一密集，分数照样能到七十，说「偏低」是自相矛盾。现在改成按情况分流：短文本说「别和整篇稿子比，能查的项目更少，这个数可能偏高也可能偏低」，长文说「这一篇的分数只代表整体」。两个方向的话不能混着说，说反了就是误导。

**两套清单不能叠在一起。** 报告里有两份指路：「先改三处」按规则排，「先改哪几段」按段排。稿子短的时候两份都出现，排法还不一样，读者要在脑子里对齐两遍——而三五段的稿子本来就一眼能看完，段号定位不值这个成本。所以少于四段只给前者。判据不是「内容重复」，是「重复且需要额外换算」。

再补两条判断原则，它们决定了这个工具会不会冤枉人：

**引用不是使用。** 写评论或分析时，经常要把套话拎出来当反面例子讲——「很多人爱写『值得注意的是』」。扫描前会先把引号里的内容遮掉（等长空格替换，位置和行号都不动），所以被引用的套话不会算到作者头上。但引号占比超过四成的文本不遮——对话体里引号是正文主体，遮掉就没东西可扫了。

**同一种手法，在不同文体里的合理密度不一样。** 破折号在评论里是节奏工具，在报告里是偷懒；「不是……而是……」在口播里是强调，在公文里是模板。所以规则可以按文体给不同阈值（`genreThresholds`）或直接排除某些文体（`exceptGenres`）：枚举结构（第一、第二、第三）在报告、技术文档、方案里放行，「首先其次最后」在评论里仍然算模板腔。这条机制是从五份真实文体样本里被逼出来的，不是拍脑袋定的。

**只说「别这么写」等于没说。** 每个文体在 `GENRES` 里都有一组 `examples`（模板腔 / 正常中文 / 差别在哪），报告处方和技能正文都会带上。理由很实际：告诉一个模型「不要用套话」，它最常见的反应是把套话换成同义词，句子结构一点没变。给一组同义的对照，它才知道改的是句子，不是词。11 个文体各两组，全部是能落到具体动作、数字或原话的例子——左边说「这件事很重要」，右边说清楚是谁、多少、什么时候。

**句子对了，结构也可能不对。** 对照管的是「这一句怎么说」，骨架（`skeleton`）管的是「先说什么后说什么」。顺序比措辞更早定型：新闻倒金字塔的导语如果放到了第三段，句子写得再干净也不像新闻稿。所以每个文体还有 3–5 条段落级骨架——报告是结论 → 依据 → 风险 → 建议，方案是目标 → 策略 → 执行 → 预算验收，口播是钩子 → 展开 → 回扣。处方、技能正文、WorkBuddy 的 SKILL.md 三处都有。

**改完要能验，不然改没改对全靠感觉。** 传 `before` 参数，报告里会多一段改前改后对照，三列分开看：**解决了**说明方向对，**还没处理**说明改得不够，**新引入**说明改出了新问题。最后这一列最容易被忽略也最伤——一边删套话一边长出新的套话，只看改后那一稿是看不出来的。另外两条自动检查：分数涨了说明改反了方向，长度掉三成以上往往会连着删掉事实，都会单独提示。

**阈值是量出来的，不是拍出来的。** 黑话那条规则原来的门槛是 0.8，意思是「一千字里用一次就报」。拿 25 份语料一量，问题露出来了：真人零星用一次行业词是 1.1–1.3 每千字（年度总结、分享会、产业评论各一处），模型写的稿子是 2.4–22.3（报告 6.99、技术文 2.37、方案 22.27）。0.8 落在真人区间**里面**，结果是 47% 的真人稿被报，比模型还高——这条规则当时根本不是在抓 AI 味，是在抓「写过行业稿」。

抬到 1.5 之后，真人零星使用全部放过（政府工作报告 1.31、年度总结 1.15、分享会 1.29、产业评论 1.13），模型密集使用全部抓住。同时删掉 proposal 的单独门槛——它原来写的 1.5 就是现在的新默认值，留着是多余的一层。

这条教训值得记住：**一条规则的阈值是从哪来的，比阈值是多少更重要。** 拍出来的下限会让规则在真人身上反复撞线，而每次撞线看起来都像「抓到了」。

**阈值之后还有一层：词表本身也可能是错的。** 2026-11 那份月度取证报告里，两条真人稿（新华网通稿 25 分、财经公众号 22 分）被判得很难看，查下去全部落在黑话这一条上。逐词统计 20 份真人稿和 11 份模型稿之后，问题不在门槛，在词表：

| 词 | 出现在几份真人稿 | 11 份模型稿命中 |
|---|---|---|
| 落地 | 5 / 20 | 3 |
| 沉淀 | 4 / 20 | 1 |
| 协同 | 4 / 20 | 1 |
| 发力 | 3 / 20 | 0 |
| 痛点 | 3 / 20 | 0 |
| 耦合 / 纵深 / 底座 | 各 2 / 20 | 0 |

八个词全部**真人用得比模型多**。留在表里就是拉低区分度——那它们量的显然不是「像不像 AI 写的」，是「这个人写不写行业文章」。

清掉这八个之后：新华网通稿 25 → **12 分**（它那 15 次里 9 次是这四个词），财经公众号 22 → **6 分**（协同 11 + 落地 8，去掉就清零），而方案稿 23 分文不动（它命中 9 次「品牌调性」「情感共鸣」「种草」这类纯营销词，密度 20.04 / 千字）。剩下的黑话表里，真人样本命中从 8/17 降到 **1/20**。

判据压缩成一句话：**一个词若在真人样本里出现得比模型样本还多，它量的就是语域，不是 AI 味。** 这句话比「这个词听起来很黑话」可靠得多——毕竟「落地」「协同」「痛点」在产业报道里是干活的词，只有在营销方案里才是泡沫。

**改稿最容易的翻车，是把好东西一起改掉。** 前面所有输出都在说「哪里不对」，用户拿着清单逐条改，顺手就把本来对的东西改没了——长句被切碎、段落被匀称、数字被换成了程度副词。所以报告末尾加了一节「这些地方不用动」，只陈述客观统计：句长变异系数够大就别为了整齐切碎，段长变异系数够大就别为了匀称凑字数，有若干处数字原话时间就是全文最不该动的部分，口语词密度够高就别换成更正式的说法。

四项判据都是量出来的阈值，不夸也不打分。它还有一个意外的用处：模型默认稿一条都拿不到——句长整齐、段落整齐、几乎没有可核对的细节，「不用动」的清单是空的。这本身就是个信号，比分数更直白。

**最管用的那段话，是最容易过时的。** 常驻提示片段每轮都在，模型写任何中文都会看到它，杠杆比工具本身还高。但它也最容易烂——规则从 69 条长起来的这几个月里，它一直停在最初的版本，讲的还是公文过渡语和万能背景，而后来补的视频腔、新闻腔、情绪套话一条都没进去。

现在补了一层「还有一种空，不在词里，在位置里」：开场先说正事、中间别打太极、结尾说结果别升华，加上「相关负责人表示」不算信源、小说写动作别写「思绪万千」。这五条对应后面加的十几条规则。

同时加了一条断言：**片段里点名的每个例子，规则必须真能抓到**。否则模型照着片段写得规规矩矩，扫描却什么都报不出来，两边各说各的。现在六个例子逐条丢给扫描，全部命中。

**改任何规则、阈值或文体画像之前，先跑 `regression.mjs`。** 它读 `corpus/manifest.json`，里面每条样本都对应一次真实误判——手写小说被判 40 分、雪中悍刀行被误报两次、虎嗅编辑的稿子被判 32 分。这个文件是防止重蹈覆辙的唯一保障，详见 [corpus/README.md](corpus/README.md)。

语料库现在有 46 条，分三组。**真人写的 21 条**覆盖全部 11 个文体：网文 2 条（手写 + 出版成名作）、小说 1 条（鲁迅《孔乙己》，公版）、财经 1 条、消息稿 2 条、年度工作报告 1 条、政府工作报告 1 条（2026 年全文，中英对照页提的中文列）、技术笔记 2 条（工程笔记 + 掘金架构选型）、口播稿 2 条、产业评论 1 条、报纸评论 1 条（人民日报评论部原文）、政策方案 1 条（工信部原文）、公众号推文 1 条（《财经》原文，经 36氪转载）、日常随笔 2 条（人民日报副刊散文 + 湖北日报散文随笔）、科普说明文 1 条（科普中国网）、构造的负样本对照 1 条。**模型默认输出的 14 条**是第十二、十三、三十八、四十二、四十三轮加的，**11 个文体各一份，两侧齐**，用来证明「该报的报了」。**照处方改写的 11 条**是第二十、三十六、四十二轮加的，十一个文体各一份，要求是 0 分——它们证明的是「处方指对了地方」，不是「换掉了那几个词」。这组还兼着新误报来源的活：改好的稿子最容易撞到规则没想到的用法，第二十轮撞出四处（落地窗被当黑话、破折号被当「的」字长链、「也就是说」被当公文过渡语、扣分并列的倍数提示挂错行），第三十六轮撞出一处更狠的——整条「段落长度过于均匀」的判据被证伪删除。真人那组的最初十二条是第四到十一轮补的，每一份都先跑出真实的误判，再改规则让它归零——顺序反了就成了拿规则去拟合样本。

最后几条是从公开原文抓的真实文本，不是构造的。《孔乙己》逼出了「对话里的短句不算碎片流」；人民日报那篇评论逼出了「报纸提要的重复不算复读」和「『与……相关的』不是翻译腔」；李书福的清华演讲实录逼出了「口播稿里反复点名主语是必要的清晰」。这几处改动有个共同点：**改的是「什么算问题」的定义，不是阈值**。阈值调低叫放水，定义改了才叫长见识。

口播稿那两条值得单说。演讲讲究自己经历，「我」连着起头是必然的；声音线性播放，听的人回看不到上一句，所以口语要反复点名主语，书面语才靠「他」「其」承前省略。同理，「唯一的障碍就是中国的碳排放权的价格」这种「的」字连挂，是边说边想的产物，不是把书面语搬过来。所以 `subjectRepeat` 的门槛按文体走（口播 8 句，书面语 3 句），`de-chain` 对 `script` 直接豁免。放宽不等于关掉——九句同主语的口播稿照样报，书面语照抄七句更报。

2026 年政府工作报告逼出的是另一类问题，它不在规则层，在检测器本身。那份报告被判了 5 组「复读」，人工核对发现没一组成立：有的两句共享「以习近平同志为核心的党中央团结带领全国各族人民」25 字套语，其余部分讲的是不同年份；有的根本不相干，只是恰好共用 18 个字的公文短语（「持续深入推进」「加快形成」）。原来的判据是「任意 18 字连续相同即重复」，在通用文本里够用，一进公文就废了——公文的固定搭配密度太高。现在加了覆盖率条件：**共用的那段至少要占较短那句的一半**，才叫复读。公式化写作和套语堆叠是两回事，前者是整句照搬，后者是用同一批词说话。

第十二轮发现的是最要命的一处：**17 条真人语料全在 0 到 14 分之间，只有我构造的负样本 87 分，中间地带是空的**。真实情况恰恰相反，最常见的是一段话有点味道但不夸张。于是就着自己写——按一份普通季度运营报告的题目，不加任何风格要求，用默认写法生成一份，结果是 **8 分 A 级，判成「基本没问题」**。那段话是标准的运营八股：围绕目标起手、在……方面铺陈、清醒地认识到、下一阶段将继续，读完不知道发生了什么。

查下来是整片盲区：**「进一步」「持续」「稳步」「切实」这一批动词前的填充副词，一条规则都没有**。补了七条——`padding-adverb`、`hedge-phrase`、`aspect-frame`、`self-reflect-cliche`、`next-stage-cliche`、`enumeration-tail`、`around-goal`，升到 54 分。

阈值不是拍的。同样的正则跑 17 份真实语料：政府工作报告 3.1 / 千字、工信部方案 2.1 / 千字，**其余 13 份全部为 0**，而这份稿子是 13 到 16 / 千字。差一个量级，取 4 到 6 之间就行。这也是为什么它没把公文体误伤——公文密度本来就低，它只是用词正式。

这条经验值得单记：**负样本只能证明「该报的报了」，证明不了「不该报的没报」**。要测漏检，得有自己的默认输出当正样本。

第十三轮就照这个思路把八个文体全测了一遍，结果全在 A 到 B 级：

| 文体 | 首跑 | 补完之后 |
|---|---|---|
| 小说 | 8 分 A | 72 分 D |
| 新闻稿 | 7 分 A | 47 分 C |
| 自媒体 | 10 分 A | 39 分 B |
| 方案策划 | 15 分 A | 23 分 B |
| 评论文 | 18 分 A | 61 分 D |
| 技术文档 | 21 分 B | 45 分 C |
| 口播稿 | 24 分 B | 72 分 D |

漏掉的东西有共同形状：**不在词里，在位置里**。开场（大家好，欢迎来到本期 / 近日 / 不知道你有没有这种感觉）、过渡（这也让我们不禁思考 / 说到这里，可能有人会问）、收尾（我们下期再见 / 生活就是这样 / 希望本文对你有所帮助）。同一个「空」，在不同文体里穿不同的衣服。

补的十一条规则按位置分组：

- **情绪与叙事**：`emotion-cliche`（思绪万千、百感交集——用成语把情绪打包）、`dramatic-pause`（时间仿佛静止、呼吸一滞）、`life-philosophy`（生活就是这样、有些东西一旦开始就再也回不去了）
- **视频腔**：`video-opening`（大家好，欢迎来到本期 / 今天我们来聊聊）、`video-outro`（我们下期再见 / 希望今天的分享对你有所帮助）
- **新闻腔**：`vague-source`（相关负责人表示、业内人士指出——没有名字的信源）、`boilerplate-success`（成功举办、圆满落幕）
- **评论文**：`think-aloud`（不禁让我们思考）、`both-reasonable`（两种观点都有其合理性）
- **通用**：`article-meta`（本文将介绍、总结一下）、`relatable-opening`（不知道你有没有这种感觉）

第十五轮又补了四条，这四条更极端：**只认位置，不管词**。

- `news-peg`（最近，一则关于 X 的新闻引发了广泛讨论）——先找个新闻由头垫一下，再开始讲道理
- `significance-inflation`（本次大会为行业发展带来了新的机遇）——事情讲完了，再补一句它的意义
- `answer-lie-in`（或许，答案就在于那些无法替代的东西）——把结论包装成一个悬而未决的答案
- `hope-inspire`（希望今天的分享对你有所启发）——一句礼貌话占掉了最后一句的位置

这四条在 17 份真人语料上同样 0 命中，只出现在模型默认稿里。补完后表里三行又往上走了（新闻稿 31→47、评论文 38→61、口播稿 67→72），真人那 17 份一分没动。

这里有一条经验：**位置类套话和词语类套话的判据不一样**。词类看「用没用这个词」，位置类看「这句话放在这儿合不合理」。同一句「让行业发展得更好」，写在报道末尾是拔高，写在采访对象原话里就是正常转述——后一种情况由引号遮蔽挡掉，不用另写规则。真正需要按文体分开的是「喜庆话」：`boilerplate-success`（成功举办、圆满落幕）在政府工作报告里是固定说法（0.35 / 千字），在新闻稿里是凑喜庆，所以给 report 和 proposal 各留了 3.0 的阈值。

阈值这次几乎不用猜。把同一批正则跑在 17 份真人语料上：**情绪套话、戏剧停顿、人生哲理、伪思考、两边都对、视频腔，六类全部 0 命中**。真人写东西根本不这么说话，所以门槛设 1.0（出现一次就报）不是激进，是它确实只出现在模板文里。

顺带修了一个评分设计问题。density 类规则原来「密度超过阈值一倍」就封顶，意味着一篇 481 字稿子里出现 10 处营销黑话，和只超一点点拿同样的 8 分。改成两倍封顶之后，方案稿从 15 升到 23，报告稿从 54 升到 99。真人那边只有两条涨了（《财经》那篇 14→22、新华网通稿 17→25），涨的全在 jargon 上，判得对——那两篇本来就黑话密集，之前是「刚好超线」和「十处黑话」同分。expect 相应放宽，理由写进了 manifest 的 history。

`rules-coverage.mjs` 管的是另一件事：**判得知不知道**不等于**判不判得出来**。这条测试给每条规则配一个必然触发的短样本，正则写错、词表漏词、阈值调高，都会在这里立刻红掉，而不是等到用户来报。它已经抓到过 `deverbal` 的一个真实缺口——词表只收了「进行讨论」，写作里常见的「进行了讨论」漏掉了。

`variants.mjs` 补的是前两者都测不到的一层：**换了说法还认不认得出来**。`rules-coverage` 的样本是照着正则的样子挑的，必然触发；真实写作没人照着正则写。同一个意思有十来种说法，词表差一个字就整条绕过去。这份测试给关键规则配三到五个同义变体，全部必须触发。

它上线第一轮就抓出四个真实的绕行：「需要注意的是」漏了（词表收了「值得注意的是」，差一个字就不认）、「持续地优化」漏了（正则没给中间的「地」留位置）、「对举句式」五种说法只认一种（「并非……而是」「不在……而在」「表面上……实际上」全绕过）、「也许答案就是坚持本身」漏了（正则收了「就在于」，没收「就是」）。这四个在旧测试下全是绿的。

这条边界值得写清楚：**词表穷举会漏，结构模式会误报**。不是没试过用模式替代穷举。试了「X 的是，」这个句式框架，结果真人写的新华社消息稿里就有两处；试了「不是 A，是 B」（不带「而」），真人写的产业评论里也有两处。真中文里这些结构是合法的，一抓就误伤。所以词表仍然只能是词表，能做的只是把变体测试焊在地上，让漏掉的那一个在测试里先红一次。

`smoke.mjs` 里的基准样本：典型 AI 腔 75 分 D 级；真人叙述 3 分 A 级；堆语气词的伪口语 20 分；碎片化短句流 42 分 C 级；汪曾祺式的短句名篇 18 分 A 级且**不触发任何节奏规则**。

最后那一条是防误报的关键用例：那段名篇的逗号比句号还少，如果判据只看逗号比就会误伤它。所以碎片化要求「几乎不用逗号」和「短句连续成串」同时成立。

## 十一对眼睛

每个文体都要有两侧样本：真人写的，和模型默认写的。

只有真人侧，证明的是「不该报的没报」；只有模型侧，证明的是「该报的报了」。缺哪一侧，那个文体的判定就有一半没验过。2026-11 之前这张表是残的——`general` 是用户不指定体裁时的默认路径，却一篇模型稿都没有；`business` 和 `webnovel` 反过来，只有真人侧。

补完之后：

| 文体 | 真人 | 模型默认 |
|---|---|---|
| general | 3 | 1 |
| media | 1 | 1 |
| script | 2 | 1 |
| fiction | 1 | 1 |
| webnovel | 2 | 1 |
| report | 2 | 1 |
| tech | 2 | 1 |
| news | 2 | 1 |
| business | 1 | 1 |
| commentary | 2 | 1 |
| proposal | 1 | 1 |

补的时候两个结果很不一样。`business` 那份模型稿首跑 **61 分 D**，八条全中——财经分析要抓的东西前面几轮已经长齐了，不需要动规则。`webnovel` 那份只有 **11 分 A**，满篇「眼中闪过一丝」「嘴角勾起一抹弧度」，一条都没报——因为此前所有规则都是给议论文和公文长的，没人替小说想过。那八条「网文腔」就是这么补出来的。

`general` 那份 67 分 D，也是自己就抓得住。

smoke 里加了一条结构性断言：**每个文体都必须有真人样本和模型默认输出样本，缺一个就红。** 逼着以后加文体时同时想清楚「人怎么写」和「模型怎么写」，而不是加完 `GENRES` 就算完事。

还有第三只眼睛：**照处方改出来的稿子**。

前两侧验证的是「判得对」——人写的别报、模型写的要报。但插件最终交给用户的是改写处方，处方管不管用是另一件事，得单独验。办法是拿一份模型稿，**只按报告上的处方改，不看规则表**，改完必须是 0 分。

十一个文体都做完了。三份是最后补的：

| 文体 | 首跑 | 照处方改完 |
|---|---|---|
| webnovel | 38 分 B | 0 分 A |
| general | 67 分 D | 0 分 A |
| business | 61 分 D | 0 分 A |

webnovel 那份最能说明问题。原文是标准网文零件拼贴——「眼中闪过一丝不易察觉的坚定」「嘴角勾起一抹淡淡的弧度」「不由得深吸一口气」「瞳孔骤然收缩」「那一刻，时间仿佛静止了」「而这一切，才刚刚开始」。八条全部命中，报告也逐条给了改法。按改法重写一遍：把「闪的那一下」换成头发被匕首割断落在脚边，把「深吸一口气」换成手心开始出汗，把「时间仿佛静止」换成对方把刀换到另一只手，把「才刚刚开始」换成山下一点一点亮起来的火光。515 字，0 分。

business 那份有个细节值得记：原文从头到尾没有一个数字。改写没有编数字——编了就违反硬约束，也骗人。改法是承认缺什么，把「估值是否合理」拆成三个能查的变量（收入口径、续约性质、推理成本），最后写一句「我这套说法最容易错在哪」。**在没有数字的稿子里，把「不知道」写清楚，比塞进几个假数字更像人写的。**

smoke 现在有三条结构性断言：真人侧、模型侧、改写侧，缺一条就红。

# 分数不能跨文体比

同一份「通篇空话」的模型默认稿，分文体摆在一起是这样的：

| 文体 | 分数 |
|---|---|
| proposal | 22 / 23 分 B |
| tech | 29 分 B |
| webnovel | 38 分 B |
| news | 40 分 C |
| report | 48 / 56 分 C |
| business | 54 分 C |
| media | 55 分 C |
| fiction | 56 分 C |
| general | 67 分 D |
| commentary | 69 分 D |
| script | 72 / 74 分 D |

差了三倍多。方案稿拿 22 分 B，报告稿拿 56 分 C，两篇的空洞程度是一样的。原因不是评分公式不对，是**每个文体能被规则够到的位置不一样**：报告有「下一步我们将」「清醒地认识到」「围绕目标」这些现成的抓手，方案的核心毛病——没有预算、没说清楚放弃什么、没有一句能核对的事实——规则表里一条都没有。

这件事如果不在报告里说，危害很直接：用户看到「22 分 B 级」会以为基本合格，然后什么都不改。

所以方案文体的 `GENRES` 里加了一个 `scoreNote`，分数落在 10 到 50 之间时，报告首屏会多一句：

> 方案策划这个文体，模型默认写法在这套规则下通常只到二十多分。不是它写得好，是它的毛病集中在「有没有预算、有没有说清放弃什么、有没有一句可核对的事实」，这几条规则查不出来。分数低别当成没问题。

这是第三次走同一条路：**规则补不上的地方，就把话说到位。** 前两次是短文本的「没查到的部分」，和长文的「局部会被平均掉」。

第四只眼睛：**同一文体里的另一个亚型。**

口播稿原来只有一份模型稿，是「分享会」那个样子——开场「大家好，欢迎来到本期」，结尾「希望今天的分享对你有所帮助，我们下期再见」。规则里正好有针对这两个位置的两条（`video-opening` / `video-outro`），很容易让人怀疑：口播稿那一套是不是靠这两条撑着的？换个亚型还认不认得出来？

所以又写了一份「年度演讲」体的 AI 稿：开场只有「各位同事，大家好」，结尾只有「谢谢大家」，视频腔那两个位置一个都没用。

结果 **74 分 D**，六条命中：结尾强行升华（「让我们一起」）、万能开场背景（「在当今」）、不仅而且（「不仅仅是工具的升级，更是」）、首先其次最后、程度副词虚高（「深刻地」）、滥用「我们」（「让我们」）。

挨着的对照是雷军的年度演讲逐字稿——10528 字、324 句、180 段，**0 分 A，零命中**。两篇都是年度演讲，一篇 AI 写的 74 分，一篇真人写的 0 分，靠的不是开场白长什么样，是里面有没有东西。

那份逐字稿也收进语料了（`script-leijun-annual-speech-2025.txt`）。选它是因为它跟李书福那篇口语完全不是一路：大量「大家想想看」「咋办呢」「实话实说」「你们知道原因吗」，还有一处自问自答、一处括号里的旁白。第二份真实口语稿要是被误判，「口头表达」那半边就站不住。

## 网文腔那八条

2026-11 补 `webnovel` 的 AI 基线时发现，模型默认写的玄幻章节只判 **11 分 A**——满篇「眼中闪过一丝」「嘴角勾起一抹弧度」，一条都没报。原因很简单：前面那些规则是给议论文和公文长出来的，没人替小说想过。

八个候选先在真人网文上逐个量过：《雪中悍刀行》23570 字、手写网文 4258 字，**全部零命中**。它们是模型写网文时的零件，不是人写小说的写法。

| 规则 | 抓什么 |
|---|---|
| `eye-flash` | 眼中／眼底／眸中 + 闪过／掠过／划过 |
| `lip-arc` | 嘴角 + 勾起／扬起／浮现／勾勒出／微微上扬 |
| `deep-breath` | 不由得／不由自主地／忍不住 + 深吸一口气／倒吸一口凉气／打了个寒颤 |
| `pupil-contract` | 瞳孔 + 骤然收缩／放大／一缩／一紧 |
| `inner-monologue` | 心中 + 暗道／暗想／一凛／一震／涌起 |
| `just-began` | 这一切……才…开始／结束 |
| `all-different` | 一切都将／已经／都…不同／变了 |
| `suddenly-punct` | 就在这时，／就在此时， |

补完 11 → 38 分 B。

这八条有个共同点值得记下来：**它们都不是错词，是「用固定零件代替观察」**。人惊讶有很多种写法，写成「瞳孔骤然收缩」是因为这一种不用想。规则抓不到「写得好不好」，但抓得到「在不在用零件」。

顺手测过一条「要知道」——虎嗅那份真人稿用了 2 次，是正常的议论用法，没加。

## 短文本要说明「没查到什么」

第一版只有一句「样本偏短，指标仅供参考」。后来发现这句话不够用——它没说清到底是什么没查。

现在报告里有一节「这段没查到的部分」，逐条列出来：

- 句子本身的检查（太短了，连一句都不完整）
- 句长与信息密度检查（要 120 字以上）
- 节奏和重复检查（要六句以上才跑得起来）
- 段落结构检查（要三段以上）

**最后一条是 2026-11 补的，之前漏了。** 结构性判据（句长、信息密度、口吻）整体挂在 120 字这个门槛上，但盲区清单里只写了句子数和段数。结果是一段六十字的稿子直接被判「0 分 A 级」，而它可能是一整句没有标点的流水账——那句话根本没跑过句长检查。报个 0 分让它放心，比报错更糟。

判断标准很简单：**每一项没跑的检查，都得写出来。** 少写一条，那个「A 级」就是在撒谎。

## 口语的长句比书面语还长

这条反直觉，数据在这。

六份口播稿的句长统计，同一套口径：

| 稿件 | 类型 | 平均句长 | 变异系数 | 逗号句号比 | 超四十字占比 |
|---|---|---|---|---|---|
| 李书福清华演讲 | 真人 | 32.2 | 0.51 | 2.26 | 32% |
| 雷军 2025 年度演讲 | 真人 | 28.4 | 0.59 | 1.81 | 26% |
| 分享会逐字稿 | 真人 | 22.1 | 0.61 | 1.81 | 13% |
| AI 分享会体 | 模型 | 19.1 | 0.51 | 1.25 | 0% |
| AI 年度演讲体 | 模型 | 22.5 | 0.33 | 1.67 | 0% |
| 按处方改写后的口播稿 | 改写 | 16.7 | 0.50 | 0.88 | 0% |

三份真人稿的平均句长都比两份模型稿长，超四十字的句子真人占一到三成，模型一个都没有。

道理不难懂：人在台上说话是一口气串到底的，中间靠逗号换气，「一句念不完」正是口语的常态。模型写口播稿反而会把句子切短切齐——它把口语理解成了短。

所以「口播稿里长句太多」这条不能做成规则。那是拿书面语的尺子量口语，量出来全是正常人。反过来「口播稿句子太整齐偏短」也不行——真正改好的口播稿最后一行恰好也是 0%。

两条都想过，两条都没加。测试里钉了一条反向断言：一段平均四十六点七字、句句带逗号的真人口语，在 script 和 general 下都必须 0 分。

## 删词只看覆盖广度，不看出现次数

上一轮删黑话词用的是「真人出现次数 ≥ 模型出现次数就删」，删掉八个（落地、沉淀、协同、发力、痛点、耦合、纵深、底座），当时是对的。

这一轮加了两份真实商业稿——一份品牌与跨平台运营分析，一份多模态模型技术博客——同样的判据立刻失控：它一口气要删二十一个词，连「赋能」「闭环」都在名单里。

原因很简单。那篇品牌分析里「触达」用了 7 次、「声量」6 次、「种草」5 次。按总次数算，一篇文章的用词习惯就变成了「整个语域都在用」。判据没错，是统计口径错了。

换成覆盖广度：多少份真人样本用到它、多少份模型样本用到它。同时满足「真人覆盖 ≥ 2 份」和「真人覆盖 ≥ 模型覆盖」才删。四十八份语料里只剩三个词够线（赋能 3 份对 2 份、闭环 2 份对 1 份、心智 2 份对 0 份）。前两个模型也在用，删了会放过真阳性；只有「心智」是真的分不开——真人两份在用，模型零份，删掉。

**顺带把上限算清楚了**：`jargon` 单项封顶 16 分。也就是说，词表里那二十四个从没在任何语料里出现过的词（爽点、痒点、北极星指标、增长飞轮、价值锚点、战略定力、双向奔赴……），最坏情况就是把一篇稿子从 A 拉到 B，判不到 D/E。它们没有证据说明会误伤，删不删都不改变结论，所以不动。

## 重复判据：量的是「共有内容有多长」

这条规则原来算覆盖率的方式是「随便截的那十八个字 ÷ 整句长度」。看着合理，实际有个致命后果：**三十七字以上的句子永远判不出来**。

三十七字的两句一字不差，覆盖率也只有 18/37 = 0.49，小于门槛 0.5，直接被当成「只是共用了十八字套语」。而 AI 复读最典型的形态恰恰是长句、整段重复——越长的重复越抓不到。

改成「这两句真正共有的最长连续内容 ÷ 较短那句」，才是想量的东西。同一对句子，一字不差就是 100%，共用二十字套语就是二十除以整句。

改完又冒出两类误报，都是结构性的，不是毛病：

- **纲要加展开**：列表项写一遍，隔几段再展开讲一遍。长度比 25:122，不是复读。
- **复沓**：一句说完，下一句整句复述再往后补一段（「…却有着自己的情怀。」→「…却有着自己的情怀，如一坛子尘封许多许多年的老酒。」）。这是章法，不是作者忘了自己写过。

所以现在的判据有三层：共有内容要占较短那句一半以上；两句长度不能差太远（短的至少是长的一半）；一句被另一句整个包住且更长的，算复沓不算复读。

四十八份语料跑下来零检出，三种构造样本分别验证了三个方向。

## 同一文体的第二个亚型

每个文体原来只有一份模型稿，这有个隐患：规则可能只认得那一份，不认得这个文体。

第 48 轮补了两个亚型，结果差得很远。

**新闻**。第一份是消息稿，四十来分。第二份写特写——场景、人物、收尾拔高。**只报了十六分，而且只报了一条「据了解」。**

那份特写里有六处更明显的毛病，规则一条都没覆盖到：「折射出的却是一座城市治理理念的转变」「托起了这座城市的体面与温度」「这看似简单的一句话背后」「他或许不会想到，正是……」「正是无数个像他这样的普通人」「一位长期关注城市治理问题的专家指出」。

消息稿不写这些，特写写。补了六条句式规则再加一条「专家指出不具名」，16 → **77 分**.

**网文**。第一份是玄幻，八条网文腔全中。第二份写都市言情，**只中了四条**——眼神闪、嘴角弧度、时间凝固、一切都将不同，这些是通用的；瞳孔收缩、深吸一口气、心中暗道、才刚刚开始是玄幻专有。另补了一条「泛起涟漪」。30 → 39 分.

结论反过来说：八条里五条是文体的，不是题材的。剩下三条只对玄幻有效，但因为阈值是「出现一次就报」，留着不误伤，就先留着.

## 机械标点不是 AI 味

第 49 轮想加一批「排版规范」规则，先量了一遍，全否了。

挑 14 个维度，在 49 份两份以上汉字的语料上算每千字密度：

| 维度 | 真人 | 模型 |
|---|---|---|
| 半角逗号粘中文 | 0 | 0 |
| 半角句号粘中文 | **0.03** | 0.00 |
| 连续空格 | **0.03** | 0.00 |
| 半角冒号、半角分号、半角问号叹号 | 0 | 0 |
| 全角数字、全角字母、制表符 | 0 | 0 |
| 中文包在英文括号里 | 0 | 0 |
| 省略号打成三个点 | 0 | 0 |

**只有真人犯了，模型一个没犯。** 想要「AI 味」的证据，量到的是「打字习惯」。

结构类也试了三条，同样不可用：

- **段首句长度**：11 个文体里 8 个是「模型更短」，但报告和方案策划反过来，而且我自己照处方改出来的三份改写稿段首句只有 10 到 18 字——比模型还短。一加规则先误伤改好的稿子。
- **括号、感叹号密度**：模型是 0，真人分别是 2.28 和 0.49。「不用」不是毛病，扣不了分。
- **每千字段落数**：模型 24.1、真人 12.4，看着能分——但那是换行习惯，网文整章用单换行，统计口径一换就翻。

顺带确认了一件事：切段用的是 `split(/\n+/)`，单换行和空行都能切，所以网文那种一行一段的排版没被当成一大段。这条已经加进测试，免得以后重构成只认空行。

**结论：标点规范、段落数量、段首句长短，这三类都不进规则表。** 测试里加了反向断言——一段带半角句号、多打空格、括号的真实叙述，必须 0 分。

## 已知边界

- **它不判断作者身份。** 这一点值得重复：真人写作和 AI 写作共享大量模式，模板腔指数高只说明文本套路多，不说明它是机器写的。拿它当 AI 检测器用，一定会误伤。
- **它是规则引擎，不是审稿人。** 抓的是模式，不理解语义。一段话可以完全避开所有规则却依然空洞，也可以命中某条规则却是自然的中文。诊断是线索，不是判决。
- **短句本身不是罪。** 插件不会因为句子短就扣分——它看的是短句有没有成串、逗号是不是几乎消失、平均句长有没有掉到文体下限以下。汪曾祺通篇短句也是好文章，这一点用测试锁住了。
- **节奏阈值是启发式的。** 文言、诗歌、意识流、法律条文这类文本会被误判，它们本来就不遵守现代叙述文的节奏统计。
- **不生成内容，也不补事实。** 缺细节时处方只要求「删掉对应的空话」，明确禁止编造。补不出的地方就该是空的。
- **「口语标记」和「具体锚点」是启发式的。** 用正则数数字和语气词。
- **「有没有具体信息」这件事，锚点密度判不了。** 曾经想用「每千字有多少数字、引语、专名」来判断一篇东西空不空，实测发现模型默认稿能堆到 55 处每千字——比政府工作报告还密。它不空，它只是编得快。专名也一样：加进判据后，8 份 AI 稿的密度从 2.4–35.6 涨到 7.3–55.7，和真人那 17 份完全重叠，分不开。所以这条规则保留，但只当「这篇几乎没有可核对的细节」的提示，不当 AI 味的判据。真想判空，得看这些数字能不能被核对，规则引擎做不到。
- **四字格堆砌也分不开。** 一度以为模型爱堆「凝心聚力、砥砺前行、锐意进取」，想加一条「三个四字词连用」的规则。实测 32 份语料：《雪中悍刀行》4.3 处每千字、孔乙己 3.2、李书福演讲 3.6，而八份 AI 基线稿多数在 0 到 2.8。真人写得比模型还密。这条没加。
- **语气词密度同样分不开。** 想用「口播稿里没有吧、呢、嘛就不像人说的」来判，实测李书福那篇清华演讲一千字里零个语气词，却通篇是口语（「你们看现在满大街都是高楼大厦，车水马龙的」「比方说」）。口语的标志不是语气词，是那些只有当面说话才会有的指代和举例，正则抓不到。这条也没加。
- **长句要看逗号，同主语要看句长。** 2026-11 补 general 真人语料时，一篇人民日报副刊散文（作者是第九届鲁迅文学奖散文杂文奖得主）被判 26 分，三处命中全是误报：主谓反复重复 14 分（连三句以「我」开头，但每句九十多字）、句子普遍过长 8 分（平均 90.7 字）、超长句占比过高 4 分。两处判据因此改了定义：**长句只在逗号少时才算欧化长句**（那篇逗号句号比 4.19，是流水句；九十多字一句带四五个逗号，是中文常态），**同主语连排只数短句**（长句里重复「我」是叙述节奏，不是机械排比）。反过来都还成立：长句没逗号的照样报，短句连着同主语的照样报——两条都写进了 smoke。
- **「段落长度过于均匀」这条判据已经删掉了。** 它原来对「段长变异系数 < 0.32」扣 7 分，存在了很久。2026-11 对 33 份语料实测，它不成立：8 份模型稿只抓到 2 份，21 份真人稿和改写稿误伤 2 份——比抛硬币好不了多少。最直接的反证是一对同构样本，新华网消息稿（人写，5 段，变异系数 0.22）和模型默认写的新闻稿（5 段，变异系数 0.19），段落结构几乎一样，靠段长根本分不开。反过来，模型稿里段落最不齐的几份（`ai-commentary` 有 0% 的段落落在均值 ±20% 里、`ai-proposal` 13%、`ai-fiction` 14%）永远不会被它抓到。而且它只在四到七段时触发，段数一多从不命中——等于在变异系数本身最不稳的区间里判案，和 `rhythm-uniform-long` 当初从 8 句提到 20 句是同一个教训。**有一份改写好的复盘稿就是因为这条误报卡在 7 分**，才把这轮证伪实验引出来。段长不整齐这件事仍然有用，但它是「不要改坏」的证据（见「这些地方不用动」），不是「写坏了」的证据。
- **常驻提示片段每轮占上下文。** 大概 900 字。觉得吵就把 `promptSection` 关掉，靠工具和技能按需用。
- **有十六条规则抓的是旧形态。** 52 条计分规则里，`translationese`、`both-and`、`either-or`、`zhengshi`、`existence`、`passive-suo`、`has-de`、`de-chain`、`redundant-conjunction`、`colon-list`、`from-to-from-to`、`dash-overuse`、`colloquial-overdose`、`net-meme`、`exclaim-overuse`、`deverbal-inflected` 在现有 25 份语料（17 份人写 + 8 份模型默认输出）上一次都没触发。原因是这些形态属于 2019–2021 那批模型的腔调——「作为一个时代的存在」「被大家所熟知」「因为……所以」每一句都挂连词，现在的模型基本不写。它们不是死规则（`rules-coverage.mjs` 里每条都有样本、都真能触发，其中十五条按正则重写句子就能命中），保留是为了接住旧模型输出和人工模仿的 AI 腔；但也别指望它们在正常稿子里出现。真正高频的是后面几轮补的那些：空转副词、万能开场、升华收尾、视频腔、新闻腔。
- **规则写得再细，也测不出「没写」的毛病。** 这套东西只看「有什么不该有」，加上节奏和结构统计。一篇稿子如果只是信息密度低、没有新东西，规则层查不出来——五条路都试过（专名密度、四字格、语气词、分块密度、段落均匀度），全部分不开真人和模型，理由见上面几条。
- **重启 DSH 才能加载。** desktop profile 是 application-owned，只在启动时组合。

## 改文案比改代码更管用

如果效果不理想，优先动 `lib/content.js`：

- `GENRES` 里每种文体的 `must` / `avoid`，直接决定处方怎么写
- `buildPromptSection` 是常驻守则，越短越好，因为它每轮都在花 token
- `buildSkillBody` 是完整方法论，按需加载，可以尽情写长（但别超过 8192 字符，否则会被工具结果修剪器截断）

要加新规则就动 `lib/rules.js`：词表型的加进 `PHRASE_GROUPS`（`mode: 'hit'` 是一次就报，`mode: 'density'` 要配上 `threshold`），语法型的加进 `REGEX_RULES`，每条都要写清 `why` 和 `fix`——报告里会原样呈现给模型。

要调节奏判定就动 `RHYTHM_PROFILES`（每个文体的平均句长下限、逗号／句号比下限、一句一段上限、连续短句上限）和 `RHYTHM_RULES`（七条节奏规则的文案与严重度）。改完务必跑 `smoke.mjs`——里面的短句名篇用例就是用来抓过度判罚的。
